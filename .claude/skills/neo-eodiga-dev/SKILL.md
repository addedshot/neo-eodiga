# 너어디가 개발 가이드

## 프로젝트 요약
전국 곳곳을 실제로 다녀온 여행 기록과 장소 정보를 모은 개인 운영 사이트다.
사이트의 중심은 **여행추천**이다. 누구와, 언제 가는지 고르면 실제 기록을 바탕으로 추천 코스를 보여주고, 예약이 필요한 곳은 예약 링크로 안내한다.
테스트 단계에서는 운영자 혼자 쓰는 개인 사이트다. 로그인과 회원 기능은 만들지 않는다.
지역은 시도와 시군구 두 단계로 나눈다. 처음에는 운영자가 사는 부산·울산·경남 콘텐츠가 많겠지만, 구조와 화면은 전국을 전제로 만든다.
혼자, 커플, 친구, 가족 누구나 자기 상황에 맞는 여행을 찾을 수 있게 한다. 특정 동행 유형(예: 아이 동반)을 기본값으로 가정하지 않는다.
수익 목적이 아니며 Vercel Hobby(비상업 전용) 플랜으로 운영한다.
사이트 이름("너어디가")은 한 곳(`src/lib/site.ts`)에서만 관리한다.

## 작업 절차 (항상 지킨다)
1. 비자명한 작업 전에는 Plan, `checklist.md`, `context-notes.md`를 먼저 작성하고 사용자 확인을 받는다. 확인 전에는 코드를 만들지 않는다.
2. 구현 전에 가정을 적는다. 불확실하면 묻고, 해석이 여러 개면 나열해서 고르게 한다.
3. 요청된 것만 최소·단순한 코드로 구현한다. 나중에 쓸지 모르는 추상화, 설정, 기능은 만들지 않는다.
4. 요청과 직접 관련된 코드만 수정한다. 인접 리팩토링은 하지 않는다. 내 변경으로 생긴 고아 코드만 정리한다.
5. 새 소스 파일 첫 줄에는 역할을 설명하는 한국어 주석 한 줄을 단다. 설정 파일은 제외한다.
6. 완료를 선언하기 전에 `npm run lint`와 `npm run build`를 실행해 통과를 확인한다. 테스트가 있으면 함께 실행한다.
7. 논리적 변경 단위마다 시맨틱 커밋을 남긴다(`feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `chore:`).
8. 에러가 나면 실제 에러 메시지, 스택트레이스, 로그를 확인한 뒤 고친다. 비슷한 패턴을 보고 추측으로 고치지 않는다.
9. 한국어 문장은 콜론(:)으로 끝내지 않고 마침표, 물음표, 느낌표로 끝낸다.
10. 장소 정보, 가격, 날짜, 좌표 같은 사실은 지어내지 않는다. 모르면 비워 두고 사용자에게 묻는다.

## 기술 스택
- Next.js(App Router) + TypeScript
- Tailwind CSS
- 콘텐츠는 MDX 파일로 관리한다(DB 없음). MDX 처리 라이브러리는 설치 시점의 Next.js 버전과 호환되는지 확인해서 고르고, 고른 이유를 `context-notes.md`에 적는다.
- 지도는 카카오맵 JavaScript SDK를 쓴다. 키는 `NEXT_PUBLIC_KAKAO_MAP_KEY` 환경변수로 받고, `.env.example`에 이름만 적는다. 키가 없거나 좌표가 없으면 지도 대신 방문 순서 목록만 보여준다. 지도 중심과 확대 수준은 특정 지역으로 고정하지 않고 표시할 장소 좌표에 맞춘다.
- 배포는 GitHub 저장소를 Vercel Hobby에 연결한다.
- 패키지 매니저는 npm을 쓴다.
- 개발 PC는 Windows다. npm 스크립트와 경로는 Windows에서 그대로 동작해야 한다.

## 1단계 범위

### 만드는 것
- **메인**: 히어로(소개 문구, 후기 목록으로 가는 버튼), 공지사항 최근 4개, "처음 오셨나요?" 이용 안내 바로가기 3개, 최근 여행후기 카드
- **여행후기 목록**: 지역(시도를 고르면 그 아래 시군구를 고르는 2단계 선택), 누구와(혼자, 커플, 친구, 가족, 아이와), 태그(실내, 야외, 무료, 비 오는 날, 대중교통) 필터. 지역 선택지에는 후기가 있는 지역만 후기 수와 함께 보여준다. 필터 상태는 URL 쿼리(`?sido=부산&sigungu=해운대구`)로 유지한다.
- **지역 목록 데이터**: 전국 시도와 시군구 목록(`content/regions.json`). 아래 "지역 데이터"를 따른다.
- **여행후기 상세**: 태그, 제목, 다녀온 날, 누구와, 인원, 동선 지도와 방문 순서, 본문(MDX), 장소 카드, 실제로 쓴 비용
- **공지사항**: 목록과 상세
- **이용 안내**: 사이트 이용 방법, 후기 잘 쓰는 법, 여행 사진 잘 찍는 법. 내용 초안은 `references/guide-content.md`에 있다.
- **공통**: 헤더, 푸터, 404 페이지
- **검색 노출**: 페이지별 메타데이터, `sitemap`, `robots`, 공유 미리보기 이미지
- **사진 위치정보 제거 스크립트**: `npm run strip-exif`로 저장소 밖 원본 폴더의 사진에서 EXIF(GPS 포함)를 지운 사본을 `public/images/reviews/<slug>/`에 만든다. 빌드 전에 `public/images` 아래 사진에 EXIF가 남아 있으면 빌드가 실패한다.

## 2단계 메뉴 (2026-11-10 확정, 상세 기능은 단계별 Plan에서 정한다)
사이트맵은 `docs/sitemap.md`에 있다.
- **여행추천** `/recommend`: 조건 고르기(누구와, 언제), 추천 코스 목록, 코스 상세 `/recommend/[slug]`(방문 순서, 장소, 예약 링크)
- **여행후기** `/reviews`: 1단계에서 만든 목록과 상세
- **지역축제** `/festivals`: 달력·목록과 축제 포스트 `/festivals/[id]`(id는 관광공사 콘텐츠 id). 자료는 한국관광공사 "국문 관광정보 서비스_GW"(15101578)이고 `npm run build-festivals`가 `content/festivals.json`을 만든다(인증키 `TOUR_API_KEY`, 주 1회 GitHub Actions 자동 갱신, 수정 시각이 같은 축제는 지난 내용을 다시 씀). 기간 미정은 빼고, 끝난 뒤 3일까지만 "종료"로 보여준 뒤 숨긴다. 1월 1일~12월 31일로 적힌 상설 행사는 목록에서 빼고 `ongoingEvents`에 담아 포스트의 "주변 상설 행사"(10km 안, 3개)로만 보여준다. 포스트는 짧은 소개(로컬 Claude Code 요약, `npm run summarize-festivals`, `content/festival-summaries.json`, 원문 해시가 다르면 원문 앞부분), 사진, 예약·신청 안내, 위치와 주변(카카오맵 링크, 주차장 1km 3곳은 공공데이터포털 주차장 표준데이터, 먹을 곳·볼거리 2km 각 3곳은 관광공사 자료), 근처 숙소(2km, 5곳), 주변 상설 행사, Open-Meteo 예상 날씨, 소개 전문(접힘), 문의, 출처 순서다. 관광공사 개발 계정은 하루 호출 한도가 있어 `--refresh`는 꼭 필요할 때만 쓴다. 예약 안내는 자료의 문장을 그대로 옮기고, 링크는 자료에 있는 주소만 쓴다(만들거나 추측하지 않는다). 사진은 공공누리 1·3유형만, 원본 주소 그대로(자르기, 크기 변환, 다시 압축 금지) 출처와 함께 넣는다. 메인에는 공지사항 옆 같은 폭으로 가까운 예정 축제 4개를 둔다.
- **여행지도** `/map`: 운영자가 다녀온 시군구 기록. 로그인 없이 만든다.
- **공지사항** `/notices`, **이용 안내** `/guide`: 헤더가 아니라 메인과 푸터에 둔다.

헤더 주 메뉴는 사용자가 정한 순서대로 지역축제, 여행후기, 여행추천, 여행지도다(`NAV_ITEMS`). 아직 기능이 없는 메뉴는 "준비 중이에요" 페이지(noindex, sitemap 제외)로 연결하고, 기능을 만들면 그 페이지를 바꾼다. 공지사항과 이용 안내는 메인과 푸터(`FOOTER_ITEMS`)에 둔다.

### 만들지 않는 것
로그인, 회원가입, 내 정보, 이용약관과 개인정보처리방침(회원이 없으므로), 회원 후기 쓰기, 댓글, 도움 됐어요, 신고, 관리자 대시보드.

## 콘텐츠 구조
```
content/
  reviews/<slug>.mdx
  notices/<slug>.mdx
  guide/<slug>.mdx
  places.json

  festivals.json        # scripts/build-festivals.ts가 만든다. 손으로 고치지 않는다.
public/images/reviews/<slug>/
```

### 지역 데이터 (`regions.json`)
- 시도는 16개다(2026-09-29 기준 공식 자료, 광주광역시와 전라남도가 전남광주통합특별시로 통합). 화면에는 짧은 이름을 쓴다(서울, 전남광주, 부산, 대구, 인천, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 경북, 경남, 제주).
- 세종은 시군구가 없는 단층 구조라 시군구 이름을 "세종시"로 둔다. 제주의 행정시(제주시, 서귀포시)는 시군구로 다룬다.
- 시군구는 기초자치단체(시, 군, 자치구) 단위다. 수원시 장안구 같은 일반구는 나누지 않고 수원시 하나로 본다.
- 각 시군구에는 행정구역 코드(시군구 5자리)를 함께 저장한다. 나중에 DB와 여행지도 색칠에 쓴다.
- 목록은 지어내거나 기억으로 채우지 않는다. 행정안전부나 공공데이터포털의 공식 행정구역 코드 자료에서 만든다. 자료를 내려받을 수 없으면 작업을 멈추고 사용자에게 파일을 요청한다.
- 행정구역은 바뀔 수 있으므로 어느 자료의 어느 날짜 기준인지 `context-notes.md`에 적는다.
```ts
type Region = {
  code: string;    // 시군구 5자리 코드
  sido: string;    // 짧은 시도 이름, 예: "부산"
  sigungu: string; // 예: "해운대구"
};
```

### 장소 (`places.json`의 한 항목)
나중에 DB 테이블로 옮길 것을 고려해 평평한 구조로 둔다.
```ts
type Place = {
  id: string;            // 영문 소문자와 하이픈, 예: "busan-science-museum"
  name: string;
  sido: string;          // regions.json의 시도, 예: "부산"
  sigungu: string;       // regions.json의 시군구, 예: "기장군"
  category: "관람" | "식사" | "숙소" | "카페" | "공원" | "해수욕장";
  lat?: number;
  lng?: number;
  hours?: string;        // 운영시간
  parking?: string;
  reservation?: string;
  stayTime?: string;     // 추천 소요 시간
  goodFor?: ("혼자" | "커플" | "친구" | "가족" | "아이와")[];  // 운영자가 직접 판단한 추천 동행
  stroller?: string;     // 유모차, 아이와 갈 때 참고
  nursingRoom?: string;  // 수유실, 아이와 갈 때 참고
  visited: boolean;      // 운영자가 직접 가봤는지
};
```
기본 항목(운영시간, 주차, 예약, 추천 소요)은 값이 없으면 "정보 없음"으로 보여준다.
`goodFor`, `stroller`, `nursingRoom`은 값이 있을 때만 보여준다.

### 후기 frontmatter
```yaml
title: 비 오는 날 국립부산과학관 반나절 코스
date: 2026-10-18          # 다녀온 날
sido: 부산
sigungu: 기장군
tags: [실내, 비 오는 날, 대중교통]
companion: 커플            # 혼자 | 커플 | 친구 | 가족 | 아이와
people: 2
kidAges: ["7~9세"]        # companion이 아이와일 때만 쓴다
transport: 대중교통
route:                    # 방문 순서, places.json의 id
  - place: busan-science-museum
    time: "10:00"
    note: 관람
cost:                     # 원 단위, 모르면 항목을 뺀다
  admission: 0
  food: 0
  transport: 0
cover: /images/reviews/<slug>/cover.jpg
author: 운영자
```
필수 필드(title, date, sido, sigungu, companion, people, tags, route)가 빠지거나, `companion`이 정해진 값이 아니거나, `sido`와 `sigungu` 조합이 `regions.json`에 없거나 `route`의 id가 `places.json`에 없으면 빌드가 실패해야 한다.

### MDX 안에서 쓰는 컴포넌트
- `<PlaceCard id="busan-science-museum" />` 장소 카드
- `<RouteMap />` frontmatter의 `route`로 지도와 순서 목록을 그린다
- `<CostSummary />` frontmatter의 `cost`로 비용 합계를 보여준다

## 디자인 규칙
UI를 만들거나 바꿀 때는 frontend-design 스킬을 함께 쓴다. 그 스킬의 원칙을 따르되, 아래 규칙은 이미 정해진 결정으로 본다.

톤은 밝고 깨끗한 하늘색이다. 혼자 떠나는 사람도, 커플도, 가족도 편하게 읽는 정보 사이트다.
문구는 특정 동행을 전제하지 않는다. 예를 들어 "아이랑 어디 갈까?"가 아니라 "이번 주말, 어디 갈까?"로 쓴다.

### 색
| 역할 | 값 |
|---|---|
| 기본 바탕 | `#FFFFFF` |
| 옅은 바탕 | `#F4F8FB` |
| 강조 바탕 | `#EAF4FF` |
| 본문 글자 | `#1B2733` |
| 보조 글자 | `#5B6875` |
| 주 색(버튼) | `#1769D1` |
| 링크 글자 | `#1565C0` |
| 포인트(로고 해) | `#F08C00` |
| 포인트 배지 | 바탕 `#FFF1DC`, 글자 `#9A5400` |
| 직접 가봄 배지 | 바탕 `#E3F6EC`, 글자 `#1B7A47` |
| 테두리 | `#E1E8EF` |
| 진한 보조 글자(메뉴, 칩) | `#3A4754` |
| 진한 테두리(입력칸, 칩) | `#CBD7E3` |

색은 Tailwind 테마에 이름을 붙여 등록하고, 컴포넌트에 hex 값을 직접 쓰지 않는다.

### 서체와 형태
- 서체는 Noto Sans KR(`next/font`)이다. 굵기는 400, 500, 700, 800만 쓴다. 제목은 800, 본문은 400, 본문 줄간격은 1.7 이상이다.
- 카드 모서리는 16~20px, 버튼은 10~12px, 배지는 완전히 둥글게 한다.
- 그림자 대신 1px 테두리로 구분한다.

### 피할 것 (AI스러운 디자인)
- 그라데이션 배경, 글로우, 블러, 네온
- 이모지 아이콘. 아이콘은 선 굵기 2의 단색 SVG를 쓴다.
- 왼쪽에만 색 띠가 있는 카드
- 의미 없는 장식, 지어낸 숫자나 후기, lorem ipsum
- 모든 섹션을 같은 크기의 카드 격자로 반복하는 구성

### 지킬 것
- 직접 찍은 사진을 크게 쓴다. 사진이 없으면 옅은 색 블록에 "사진" 자리표시를 둔다.
- 터치 영역은 44px 이상, 글자 대비는 4.5:1 이상이다.
- 모바일 우선으로 만든다. 좁은 화면에서는 메뉴가 줄바꿈되거나 메뉴 버튼으로 바뀐다.
- `<button>`, `<a href>`, `<label>`을 제대로 쓴다. div에 onClick을 달지 않는다.
- 다른 사람의 얼굴이 알아볼 수 있게 나온 사진은 쓰지 않는다. 아이 얼굴은 특히 주의한다.
